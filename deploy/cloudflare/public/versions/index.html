What happened to QRWTY

QRWTY, a short-link and QR code service, became a test bed for Jeeves, a tool that generates backend code from a diagram. For two days in November 2026 two builds of the same service ran side by side: arm A with Jeeves, arm B without it. On 2026-11-15 the owner wound both down. These pages keep what each one produced.

Timeline

Times are UTC.

  1. 2026-11-13The plan. A public link and QR service: guest links that never expire, free and paid accounts, and a click recorded durably before every redirect. Two builds of it against the same frozen inputs, one with Jeeves and one without, each with a ledger of every model request. Cloud work stays within the Google Cloud trial credit and the Cloudflare free plan.
  2. 2026-11-14 05:20The shared inputs are frozen. The contract, the product rules and an acceptance test suite both arms run (the neutral pack, later revised up to v1.6).
  3. 2026-11-14 06:00–09:15Arm A draws the backend in Jeeves (revision 83: 16 tiles, 27 links, 14 modules) and exports it. An audit of what Jeeves can generate for it finds gaps, written up as Jeeves units QG01–QG20.
  4. 2026-11-14 09:18Arm B starts from an empty repository: its own architecture, runtime, guest links, sessions and accounts, a redirect that publishes each click before answering, and abuse controls (B00–B06, done 2026-11-15 00:10).
  5. 2026-11-14 09:33 → 2026-11-15 06:07Jeeves's QG fixes. 17 units change Jeeves's templates so generated code holds up in production: exact request bytes, a non-root image, database calls that settle while PostgreSQL stalls, Pub/Sub channels and loops, verified TLS, endpoints from the environment and more. Two reviews (QGR1, QGR2) check them.
  6. 2026-11-14 23:07qrwty.io changes hands. The original landing page gives way to a placeholder on a new Cloudflare Worker.
  7. 2026-11-15 01:32One visual direction is chosen in the owner's style, with a clickable prototype of every screen.
  8. 2026-11-15 04:22B goes live at b.qrwty.io: Cloudflare in front of a Google load balancer, Cloud Run, Cloud SQL, Memorystore and Pub/Sub. Auth0 sign-in follows at 05:57, click analytics at 10:56.
  9. 2026-11-15 06:10The freeze. A's generator is fixed at Jeeves 4e87f97. At 08:12 revision 84 is exported into A's repository: 2,926 generated backend lines that build and start, with every product route answering 501.
  10. 2026-11-15 08:38–11:42A writes its first slice by hand: durable guest link creation, 720 lines on top of the 2,925 generated lines it kept.
  11. 2026-11-15 11:34The wind-down. The owner decides the run has taught Jeeves enough. B stops after analytics; A stops after the guest-link slice and one live deploy.
  12. 2026-11-15 11:42–12:12B is recorded, then torn down, b.qrwty.io's records included.
  13. 2026-11-15 11:46–13:27A's one live deploy. The generated app runs on Cloud Run, Cloud SQL, Memorystore and Pub/Sub for about an hour and a half, is probed, recorded and torn down (about USD 0.23). It finds five more Jeeves gaps.
  14. 2026-11-15 11:10–13:37Jeeves batch 3 fixes gaps A found (QG28–QG34), and its review finds no defect. The next Jeeves plan, drawn from both arms, can start.
  15. 2026-11-15This site. The records go up on qrwty.io, and the results go in the repository's README.
