## Stub changes (application files)

- **`link-operations/settings.ts` (new).** It defines the four setting kinds the stub declares, each
  checked in the configuration pass:
  - `QRWTY_PUBLIC_ORIGIN_URL`: `text()` plus Q06's origin-only check;
  - `LINK_REPLAY_KEYS`: `secret()`, the file `link-replay-keys`, plus Q06's ring parser;
  - `QRWTY_REPUTATION_CREDENTIALS`: optional `text()`, `metadata` only;
  - `QRWTY_TEST_HOOKS`: optional `text()`, `on` only.

  `publicOrigin` moved here from `service.ts`. The key ring keeps Q06's line format, so the local
  helper `app-secrets.sh` and the GCP secret are unchanged.
- **`link-operations/service.ts`.** `linkOperationsFromEnvironment()`, which read `process.env` and
  `readSecret` when the module loaded, became `linkOperationsFor(settings)`. It builds the
  operations from `dependencies.settings` on the first request and keeps them per settings object,
  so each process keeps one test-hook state and one token cache.
- **What changed in behaviour.**
  - Every startup failure now reads `Invalid setting <NAME>`, which the generated pass words, never
    a value. The old message was Q06's own (`Unreadable credential link-replay-keys…`).
  - An empty `QRWTY_TEST_HOOKS=` now counts as unset, not as invalid.
  - The key ring can be read from `JEEVES_SECRET_LINK_REPLAY_KEYS_FILE` (QG34).
- **Not adopted:**
  - `transaction` and `idempotent`: neither would remove code (AG-18);
  - `defineRoutes`: Link operations has one route.
- **Tests (application files).**
  - `test/unit/configuration.test.ts` reads the stub's declaration through the generated
    `readSettings`. It covers each refusal, the file variable, and the per-settings cache.
  - `test/unit/google-credentials.test.ts`: its startup case does the same.
  - `create.test.ts` and `concurrency.test.ts`: their request literals gain QL02's `rawPath` and

## Other contracts followed

- **QG29 (`JEEVES_MIGRATE_TLS`, no default).**
  - Local overlay (`infra/app-overlay/compose.override.yaml`): setup-migrate sets
    `JEEVES_MIGRATE_TLS=verify-full` and `JEEVES_MIGRATE_CA_FILE=/qrwty-tls/ca.crt`, in place of
    `PGSSLMODE` and `NODE_EXTRA_CA_CERTS`.
  - Production preflight: `JEEVES_MIGRATE_TLS` is required for `migrate`. It must be `verify-full`,
    or `disable` only when `PGHOST` is a socket directory. This replaces the old `PGSSLMODE` rule.
  - `infra/gcp/run.tf`: the migration job sets `JEEVES_MIGRATE_TLS=disable`, since it reaches Cloud
    SQL through its Unix socket.
- **QG34 (`JEEVES_SECRET_<NAME>_FILE`).**
  - The preflight (`scripts/qrwty-production-profile.mjs`, in the overlay and installed) no longer
    links secret volumes into `/tmp/qrwty-secrets`, and the Cloud Run commands drop
    `SECRET_DIR=/tmp/qrwty-secrets`.
  - Each credential a process reads must have its file variable naming its own volume,
    `<QRWTY_SECRET_MOUNT_DIR>/<name>/value`. An `AUTH_DISABLED` cache may name `/dev/null`.
  - A file variable for a credential the process doesn't read is refused, so it can't stand in for a
    checked one.
  - `infra/gcp/locals.tf` (`credential_sets`, `secret_files`) sets the variables per process.
  - `infra/local/profile-check.mjs` does the same in `profile` mode.
  - `production-profile.json` drops `linkDir`.
- **QG28 (subscription per loop stub).** `infra/gcp/locals.tf` names the subscription
  `click-events--analytics-worker--analytics-worker-click-aggregator`, and its dead-letter topic the
  same with `.failed`. Locally, `setup-pubsub` created those names, and the worker's startup probe
  found its subscription ([startup lines](records/startup-lines.jsonl)).
