## Background

The owner chose Auth0's free tier as the managed issuer for both arms' staging (owner decisions §12).
The frozen web flow is unchanged. Each arm has its own application and API audience, and test users
live in one shared, email-only Username-Password connection.

Run against a staging deployment, the v1.5 oracle fails in two ways that the pack itself causes.
Both affect every arm alike.

1. **Fixed account names.** The oracle signs in only as the literal names `oracle-alice`, `oracle-bob`
   and `oracle-operator`. These are fixed by the adapter schema's `const`, `fixtures/accounts.ts`, and
   direct calls in A04, A06 and A14. An email-only connection rejects them. One shared connection
   can't hold one `oracle-alice` per arm, and staging has no operator account.
2. **Repeated refused logins.** After a refused login, the HTTP form driver (`Api.signIn`) posts the
   form again, up to 10 times. Ten is exactly Auth0's brute-force threshold, so the accounts get
   blocked.

The driver itself already works on Auth0 Universal Login: with a valid email it signs in and returns
to `returnTo`.

## Objective

Publish **pack v1.6**: a self-contained copy of v1.5 with exactly these changes.

**(a) Per-account login identifiers.**
- The adapter's `identity` section maps each oracle account (alice, bob, operator) to its own login
  identifier and its password source. Local adapters keep today's names as the default.
- The password comes from an adapter command that prints it once to stdout. Choose the exact shape,
  for example `identity.passwordCommand` with an `{account}` argument. Never log, store or echo the
  password in results.
- An account the adapter doesn't map is reported `blocked` with its reason. For example, the operator
  is blocked when a staging deployment has no operator account. It is never failed.
- Update the schema, `fixtures/accounts.ts`, A04, A06 and A14, and every other caller that names an
  account literally.

**(b) No repeated refused login.** One sign-in attempt per account per call, never more. A refused
login fails that check with a clear reason and is never posted again. Retries belong only to network
errors before the form is posted.

**(c) Self-tests.** Add two cases, and keep every existing case's result:
- `signin-lockout`: an issuer double that locks an account after 3 refused posts. The v1.6 oracle must
  post at most once. Prove that v1.5's driver locks it.
- `signin-mapped-identifier`: an issuer double that accepts only emails. With mapped identifiers it
  passes; with v1.5's fixed names it fails.

- Update `status.json`'s pack fields.
