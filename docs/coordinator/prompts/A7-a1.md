### Stripe, test mode only

Load `~/.config/qrwty/stripe.env` (`STRIPE_SECRET_KEY` = `sk_test_…`, `STRIPE_PUBLISHABLE_KEY` =
`pk_test_…`) with `set -a; . file; set +a` inside the same shell command.
- **Refuse live keys.** If the secret key doesn't start with `sk_test_`, stop and report.
- **Test-mode objects.** Create, idempotently and named with `qrwtya`, a product "QRWTY Paid", a
  USD 5.00/month price, a webhook endpoint and a customer-portal configuration.
- **Webhook endpoint.** Point it at a public path on qrwty.io that the Worker forwards to Billing
  API, for example `https://qrwty.io/webhooks/stripe`. Choose the simplest route A's ingress allows,
  and record it.
- **Secrets.** Store the webhook signing secret and the secret key in Secret Manager.

### Server

- **Checkout.** Use a server-owned customer and price mapping, with an idempotent Checkout Session.
  Success and cancel return to `https://qrwty.io/billing?checkout=…`.
- **Webhooks.** Verify the Stripe signature over the exact raw bytes (QG01 gives the raw body)
  before parsing. Store events durably in an inbox before answering 2xx. Process them repeat-safe,
  with bounded retries and lease fencing.
- **Entitlements.** Q10b's matrix applies: free is 5 links, a 7-day lookback and 1 export; paid is
  50, 90 days and 20, as Q00 froze them.
- **Transitions.** Handle paid-through, cancel, past-due and grace. Enforce owned create and claim
  usage in the Links transaction, and meter the CSV export allowance.
- **Portal.** Create a customer-portal session for **Manage payment**.
