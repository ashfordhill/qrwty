## Objective

1. **Q09, abuse controls**, as `docs/plans/production-build/units.md` defines it and pack v1.6's
   frozen `decisions.md`, `http-contract.md` and `product-contract.md` specify it. Build it in A's
   application-owned stub bodies and product SQL:
   - **Guest admission:** distributed and bounded, in Valkey. Key it on a keyed hash of the client
     address (IPv4 /32, IPv6 /64); never store the raw address. Cover the shared-NAT case.
   - **Account limits:** exact and transactional where the contract defines them.
   - **Reputation:** keep Web Risk as it is. Creation fails safely when the scanner is out, and
     redirects keep working for existing links.
   - **Reports:** bounded. A report never blocks a link automatically.
   - **Operators:** privileged block and unblock, recording actor and reason. They propagate through
     the cache within the validity deadline and leave tombstones. A small operator path is enough,
     for example a CLI script that calls an operator-only route.
   - **Operator identity:** `OPERATOR_SUBJECTS` stays empty unless the owner later asks to be an
     operator.
   - **Client address:** the Worker passes the visitor's address in a header the services can trust,
     for example an HMAC-signed header from the Worker with its key in Secret Manager. Use the
     simplest design that A's code supports, and record it.
2. **A3b leftovers:**
   - **Auth0 user on account deletion.** Delete-my-account also deletes the Auth0 user. Use an M2M
     app `qrwtya-account-erasure` that has **only** `delete:users`, with its credential in Secret
     Manager.
   - **Local Compose profile.** Optional. Add Session API's settings and secrets to the local
     Compose profile only if it's quick.
3. **Billing return route.** Let the Worker route `/billing` and `/billing?checkout=…` to the app,
   ready for A7.
4. **Deploy.** Roll out with
   `QRWTY_REDEPLOY_DIR=.scratch/A6/redeploy infra/gcp/scripts/redeploy.sh HEAD`.
5. **Live smoke on qrwty.io:**
   1. eleven quick guest creates from one address: the eleventh gets 429 with `Retry-After`, and
      the UI shows it;
   2. Web Risk's malware test URL is refused;
   3. a report is accepted;
   4. an operator block, done with the CLI against a test link, makes the short link answer 403
      within the cache deadline, and an unblock restores it;
