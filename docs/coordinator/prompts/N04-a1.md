**Background.** An arm's review found two oracle checks that a weak implementation can pass. Both arms
are affected equally.
- **F01** ("Valkey refused, stalled and broken during hot redirects … no stampede, database queries
  bounded") is too weak. A per-process route cache inside each replica serves the hot slugs through the
  whole fault, so the database-fallback and stampede bounds are never exercised.
- **F06** ("traffic beyond the publisher queue bound … memory stays bounded") sizes its burst as 3 × the
  arm's own declared bound. A small declared bound makes the burst small, so the check rewards it. The
  memory it measures is mostly the cost of accepted sockets.

**Objective.** Publish **pack v1.4**: a self-contained copy of v1.3 with exactly these changes.
- **(a) F01.**
  - **New fault point.** Add a neutral test-control fault point, `clear-route-caches`, to the adapter
    schema and the test-control docs. Its contract: every replica drops its per-process route cache
    entries. It leaves the shared cache and the database alone. An arm without per-process route caches
    implements it as a no-op that returns success.
  - **How F01 uses it.** F01 calls it on every replica right after injecting each cache fault and before
    sending that fault's hot redirects.
  - **Missing fault point.** If the adapter doesn't declare it, F01 is `blocked` with the reason
    "adapter has no clear-route-caches fault point".
- **(b) F06.**
  - **Burst size.** The burst for "traffic beyond the publisher queue bound" becomes a pack-fixed size:
    the larger of 2,000 concurrent GETs and (the arm's declared publisher queue bound + its declared
    admission bound + 1). A small declared bound no longer shrinks the burst.
  - **Memory measure.** Memory becomes growth above a baseline taken with the same number of connections
    held open and idle, so the cost of the sockets themselves cancels out. Keep the existing limit
    (128 MB), unless a frozen document states another.
  - **What passes.** A 503 without `Location` passes whether the refusal comes from admission or from the
    publisher queue.

  Record the exact rule and its reasons in the decisions file.
- **(c) Self-tests.** Add two cases to the self-test, and keep every existing case's expected result:
  - **`F01-inprocess-stampede`**, expected `failed`: a double whose per-process cache hides an unbounded
    database fallback. Once the cache is cleared, it sends one database query per request.
  - **`F06-small-bound-unbounded-queue`**, expected `failed`: a double that declares a tiny bound but
    queues without limit behind admission, so memory grows past the limit.
- **(c2) Monotonic timing (coordinator addition, neutral).** This host's wall clock jumps forward about
  3.6 s every 36 s (WSL2). Any latency the oracle measures with `Date.now()` or `new Date()` can be
  inflated by one jump. Measure every duration and deadline check with a monotonic clock
  (`performance.now()` or `process.hrtime.bigint()`), and keep wall-clock time only for timestamps
  that are recorded or compared with an arm's own clock. List each check you changed. Add a unit test
  that fakes a wall-clock jump during a measured interval and shows the measured duration is
  unaffected.
