## Objective

Do Q11 of `docs/plans/production-build/units.md` and the "Q11 review package" of `design-brief.md`,
exactly. Read the whole brief.

### For each direction
- **Screens:** create, successful result, library, analytics, and pricing/upgrade/billing, with
  real-length content. Each screen also shows the core error and empty states from the brief.
- **Variants:** light and dark, desktop (1440×900) and mobile (360×800).
- **A token sheet:** the CSS custom properties, the same names in both directions.
- **Three specific design choices explained,** not adjectives.
- **Accessibility:** a reduced-motion and solid-surface treatment.
- **A practical QR export sample.**
- **Rendering cost:** measure the glass rendering cost on the agreed mobile profile, if the direction
  uses glass.

### Shared
- **One clickable local prototype** with a skin switch and a light/dark switch: static HTML, CSS and
  JS under `docs/design/prototype/`, no build step, and no external requests at runtime.
- **An Excalidraw flow sheet** of the main flows (`.excalidraw` source plus a PNG render), kept apart
  from the high-fidelity prototypes.
- **A frozen list of accessible names:** the role and name of every control the UI tests will drive,
  in `docs/design/accessible-names.md`. A later pack amendment freezes it for the oracle, and both
  arms' UIs must use these names.
- **A competitor review:** current public TinyURL, Bitly, Dub and one QR generator, by task. Record
  the date, the concrete findings and the weaknesses. Use the web only for this. Don't clone their
  layouts or reuse a generic component theme as the whole design.
